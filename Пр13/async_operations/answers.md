# Ответы на вопросы для самоконтроля (Практическая работа №13)

## 1. В чем разница между `Promise.then().catch()` и `async/await` с `try/catch`? Когда следует использовать каждый подход?

*   **`Promise.then().catch()`**: Это классический способ работы с промисами. Он хорошо подходит для создания цепочек асинхронных операций, где результат одной операции передается в следующую. Код может стать менее читаемым при глубокой вложенности или сложной логике обработки ошибок.
*   **`async/await` с `try/catch`**: Это синтаксический сахар над промисами, который позволяет писать асинхронный код так, как будто он синхронный. Это значительно улучшает читаемость и упрощает обработку ошибок, особенно когда нужно выполнить несколько последовательных асинхронных операций. `try/catch` интуитивно понятен разработчикам, знакомым с синхронным кодом.

**Когда использовать:**
*   Используйте `async/await` по умолчанию для большинства задач, особенно для последовательных операций и сложной логики.
*   Используйте `.then().catch()` для простых цепочек промисов или когда нужно обработать результат промиса "на лету" без прерывания потока выполнения.

## 2. Как работает `Promise.all` и что происходит, если один из промисов в массиве завершается ошибкой?

`Promise.all` принимает массив промисов и возвращает новый промис, который resolves только тогда, когда **все** промисы в массиве успешно resolved. Результатом будет массив значений, соответствующих каждому промису.

Если **хотя бы один** промис в массиве будет rejected, то `Promise.all` немедленно rejects с причиной отказа этого первого промиса. Остальные промисы продолжат выполняться, но их результаты будут проигнорированы.

## 3. В чем разница между `Promise.all`, `Promise.race` и `Promise.allSettled`? Приведите практические примеры использования каждого.

*   **`Promise.all`**: Ждет выполнения **всех** промисов. Если один падает — падает всё.
    *   *Пример*: Загрузка нескольких независимых ресурсов (данных пользователя, его постов, комментариев), которые нужны все вместе для отображения страницы.
*   **`Promise.race`**: Возвращает результат **первого** завершившегося промиса (неважно, успешно или с ошибкой).
    *   *Пример*: Реализация таймаута для запроса. `Promise.race([fetchData(), timeout(5000)])`. Если `timeout` сработает первым, запрос будет считаться неуспешным.
*   **`Promise.allSettled`**: Ждет выполнения **всех** промисов и возвращает массив объектов со статусом (`fulfilled` или `rejected`) и значением/причиной для каждого. Никогда не rejects.

## 4. Как реализовать повторные попытки (retry logic) для асинхронных операций с экспоненциальной задержкой?

Логика реализуется с помощью цикла (например, `for` или `while`). Внутри цикла асинхронная операция оборачивается в `try/catch`.
1.  В блоке `try` выполняется операция. Если она успешна, результат возвращается, и цикл прерывается.
2.  В блоке `catch` проверяется, достигнут ли лимит попыток.
3.  Если лимит не достигнут, вычисляется время задержки по формуле `baseDelay * (multiplier ^ attemptNumber)` (экспоненциальный backoff).
4.  Выполняется ожидание (`await delay(delayTime)`).
5.  Цикл переходит к следующей итерации.
6.  Если лимит попыток достигнут, ошибка пробрасывается дальше.

## 5. Что такое "состояние гонки" (race condition) в асинхронном коде и как его избежать?

"Состояние гонки" возникает, когда поведение программы зависит от непредсказуемой последовательности или времени завершения асинхронных операций. Например, два запроса к API могут вернуться в неожиданном порядке, и последний ответ перезапишет данные от первого, более актуального запроса.

**Как избежать:**
*   Использовать флаги или токены отмены (AbortController) для игнорирования устаревших ответов.
*   Правильно управлять состоянием приложения, чтобы обновления происходили только от ожидаемого источника.
*   Использовать очереди для последовательной обработки зависимых операций.

## 6. Как работает кэширование результатов асинхронных запросов и какие стратегии кэширования существуют?

Кэширование сохраняет результаты предыдущих запросов (обычно в памяти, например, в `Map` или `Object`). При повторном запросе с тем же URL сначала проверяется наличие данных в кэше. Если они есть, они возвращаются мгновенно, иначе выполняется реальный запрос, и его результат сохраняется в кэш.

**Стратегии:**
*   **Cache-First**: Сначала ищем в кэше, если нет — делаем запрос.
*   **Network-First**: Всегда делаем запрос, но сохраняем результат в кэш для будущего использования.
*   **Stale-While-Revalidate**: Возвращаем устаревшие данные из кэша сразу, но в фоне обновляем кэш свежими данными.
*   **TTL (Time-To-Live)**: Данные в кэше имеют срок годности и удаляются/обновляются по истечении времени.

## 7. Какие методы оптимизации производительности можно применить при работе с множественными асинхронными операциями?

*   **Параллельное выполнение**: Использовать `Promise.all` для независимых операций вместо последовательного `await`.
*   **Кэширование**: Избегать повторных одинаковых запросов.
*   **Дебаунсинг и троттлинг**: Ограничивать частоту вызова функций (например, при вводе в поле поиска или скролле).
*   **Ленивая загрузка (Lazy Loading)**: Загружать данные или ресурсы только тогда, когда они действительно нужны.
*   **Пагинация и виртуализация**: Не загружать и не рендерить огромные объемы данных за раз.
*   **Оптимизация запросов**: Запрашивать только необходимые поля, использовать более эффективные эндпоинты API.

## 8. Как обрабатывать ошибки в цепочках промисов и предотвращать "проглатывание" ошибок?

*   Всегда добавляйте `.catch()` в конец цепочки промисов для перехвата любых необработанных ошибок.
*   При использовании `async/await` оборачивайте асинхронный код в блоки `try/catch`.
*   Не оставляйте промисы "висящими" (unhandled promise rejections). Современные браузеры и Node.js предупреждают об этом.
*   В цепочках `.then()` можно добавлять `.catch()` после конкретного шага, чтобы обработать ошибку локально и позволить цепочке продолжить выполнение (возможно, с другим значением).

## 9. В чем преимущества использования `async/await` по сравнению с традиционными промисами и обратными вызовами?

*   **Читаемость**: Код выглядит почти как синхронный, его легче читать и понимать.
*   **Обработка ошибок**: Использование привычных блоков `try/catch` вместо цепочек `.catch()`.
*   **Отладка**: Stack traces в `async/await` обычно более информативны и проще для отладки, чем в цепочках промисов или колбэков.
*   **Избегание "Callback Hell"**: Полностью устраняет проблему глубоко вложенных обратных вызовов.
*   **Условная логика**: Легче интегрировать асинхронные операции с условными операторами (`if/else`) и циклами (`for/while`).

## 10. Как отлаживать асинхронный код и какие инструменты разработчика наиболее полезны для этого?

*   **Консоль браузера (Console)**: Используйте `console.log`, `console.table`, `console.time/timeEnd` для отслеживания потока выполнения и времени операций.
*   **Инструменты разработчика (DevTools)**:
    *   **Вкладка Network**: Для мониторинга всех сетевых запросов, их статуса, времени ответа и payload.
    *   **Вкладка Sources**: Для установки breakpoints прямо в асинхронных функциях и пошаговой отладки.
    *   **Вкладка Performance**: Для профилирования и выявления узких мест в производительности асинхронных операций.
*   **`debugger` statement**: Можно вставить в код для принудительной остановки выполнения.
*   **Специализированные библиотеки**: Например, `why-is-node-running` для Node.js или расширения для браузера, помогающие отслеживать незавершенные промисы.
