# Ответы на вопросы для самоконтроля

## 1. Какие три основные области работы с файлами в Git и чем они отличаются?

1. **Рабочая папка (Working Directory)** - где вы редактируете файлы
2. **Индекс (Staging Area)** - промежуточная область, куда добавляются файлы перед коммитом  
3. **Репозиторий (Repository)** - где хранятся все коммиты и история изменений

## 2. Что происходит при выполнении команд:

- **git add**: добавляет изменения из рабочей папки в индекс (подготавливает к коммиту)
- **git commit**: сохраняет изменения из индекса в репозиторий, создавая снимок состояния
- **git push**: отправляет локальные коммиты на удалённый репозиторий (GitHub)

## 3. Почему важно писать информативные сообщения к коммитам?

Информативные сообщения помогают понять, что именно было изменено в каждом коммите, облегчают поиск нужных изменений в истории и упрощают работу в команде. Сообщения типа "исправление" или "update" не дают полезной информации.

## 4. Чем отличается git add имя_файла от git add .?

- **git add имя_файла**: добавляет в индекс только указанный файл
- **git add .**: добавляет в индекс все изменённые и новые файлы в текущей директории

Лучше использовать `git add имя_файла`, когда нужно добавить только конкретные файлы, и `git add .`, когда нужно добавить все изменения сразу.

## 5. Что показывает команда git status?

Команда git status показывает текущее состояние репозитория:
- какие файлы изменены, но не добавлены в индекс
- какие файлы добавлены в индекс и готовы к коммиту  
- какие файлы не отслеживаются Git

Вывод меняется на разных этапах: после изменения файлов, после git add, после коммита.

## 6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?

Эта команда добавляет удалённый репозиторий и связывает его с локальным. Слово "origin" - это стандартное имя (псевдоним) для основного удалённого репозитория. Можно использовать любое другое имя, но origin - общепринятый стандарт.

## 7. Зачем нужен флаг -u в команде git push -u origin main?

Флаг -u (или --set-upstream) устанавливает связь между локальной веткой и удалённой. После этого можно использовать просто `git push` без указания ветки и remote. Это нужно только при первой отправке ветки на удалённый репозиторий.

## 8. Что такое ветка по умолчанию и какая у вас создалась?

Ветка по умолчанию - это основная ветка, в которой начинается разработка. У меня создалась ветка **main** (в старых версиях Git использовалась master). Это важно, потому что main обычно считается стабильной версией проекта.

## 9. Как просмотреть историю коммитов?

История коммитов просматривается командой `git log`. Для каждого коммита показывается: хэш коммита, автор, дата и сообщение коммита.

## 10. Что произойдёт, если сделать изменения в файле, но не выполнить git add перед git commit?

Если не выполнить git add, то изменения останутся в рабочей папке и не попадут в коммит. Команда git commit без предварительного git add создаст коммит без этих изменений (или выдаст сообщение, что нечего коммитить, если индекс пуст).
