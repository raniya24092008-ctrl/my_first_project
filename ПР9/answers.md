# Практическая работа №9. JavaScript: базовые алгоритмы

## Ответы на вопросы для самоконтроля

## 1. В чем разница между временной сложностью O(n) и O(n²)? Приведите примеры алгоритмов с каждой сложностью.

**Ответ:** Временная сложность показывает, как растёт время работы алгоритма, когда растёт размер входных данных `n`.

- **O(n)** это линейная сложность: если данных в 10 раз больше, то и работает он примерно в 10 раз дольше. Примеры из работы: `findMax` (один проход по массиву), `reverseString`, `fibonacci`, `factorial`.
- **O(n²)** это квадратичная сложность: если данных в 10 раз больше, то работает примерно в 100 раз дольше. Обычно это вложенные циклы. Пример: `bubbleSort` (цикл внутри цикла).

Для наглядности: для 1000 элементов линейный алгоритм делает порядка 1000 операций, а квадратичный порядка 1 000 000.

## 2. Как работает алгоритм бинарного поиска и почему его сложность O(log n)?

**Ответ:** Бинарный поиск работает только с **отсортированным** массивом. Мы смотрим на средний элемент:

- если он равен искомому, то поиск закончен;
- если он меньше искомого, то дальше ищем только в правой половине;
- если больше, то только в левой.

Так на каждом шаге область поиска уменьшается вдвое. Например, в `[1, 3, 5, 7, 9]` ищем `7`: средний элемент `5` меньше, значит берём правую часть `[7, 9]`, и находим `7`. Количество шагов равно тому, сколько раз можно поделить `n` пополам, то есть `log₂(n)`. Для миллиона элементов это всего около 20 шагов, поэтому сложность `O(log n)`.

## 3. Какие преимущества и недостатки у пузырьковой сортировки по сравнению с другими алгоритмами сортировки?

**Ответ:**

**Преимущества:**
- очень простая в реализации и понятная;
- если сортировать на месте, дополнительная память не нужна (`O(1)`); в моей реализации сортируется копия массива, поэтому память `O(n)`, зато исходный массив не меняется;
- устойчивая (равные элементы не меняют порядок);
- с проверкой `swapped` на уже отсортированном массиве работает за `O(n)`.

**Недостатки:**
- в среднем и в худшем случае `O(n²)`, поэтому для больших массивов очень медленная;
- `Quick Sort`, `Merge Sort` и `Heap Sort` работают за `O(n log n)` и намного быстрее.

Поэтому пузырьковую сортировку используют в основном для обучения и для очень маленьких массивов.

## 4. Как можно оптимизировать функцию проверки на простое число для больших чисел?

**Ответ:** Идеи оптимизации, начиная с самых простых:

1. Проверять делители только до `√n`, потому что если у числа есть делитель больше `√n`, то есть и парный меньше `√n`.
2. Сразу отбросить чётные числа и числа, кратные 3, а потом проверять только делители вида `6k ± 1` (5, 7, 11, 13...). Именно так сделано в моей функции `isPrime`:

```js
for (let i = 5; i * i <= number; i += 6) {
    if (number % i === 0 || number % (i + 2) === 0) return false;
}
```

3. Если нужно проверить много чисел, то лучше заранее построить решето Эратосфена.
4. Для очень больших чисел (например, в криптографии) используют вероятностные тесты, например тест Миллера-Рабина.

## 5. В чем разница между рекурсивной и итеративной реализацией алгоритма Фибоначчи?

**Ответ:**

- **Рекурсивная** (`fib(n) = fib(n-1) + fib(n-2)`): код короткий, но одни и те же значения считаются много раз. Сложность растёт экспоненциально (примерно `O(2ⁿ)`), к тому же глубина рекурсии растёт вместе с `n`, и на больших `n` может быть переполнение стека.
- **Итеративная** (с циклом): каждое число считается один раз, сложность `O(n)` по времени. Память `O(1)`, если хранить только два последних числа.

В моей работе реализован итеративный вариант. Массив в нём нужен только потому, что функция по заданию должна вернуть первые `n` чисел. Рекурсивный вариант можно ускорить с помощью мемоизации (запоминания уже посчитанных значений).

## 6. Какие методы отладки вы использовали при реализации алгоритмов?

**Ответ:**

- `console.log()` для вывода промежуточных значений и результатов;
- функция `runTest()`, которая сравнивает ожидаемый и полученный результат и показывает на странице ✅ или ❌;
- вкладка Console в DevTools браузера (F12), где видны результаты и ошибки;
- тесты на крайние случаи (пустой массив, ноль, отрицательные числа), которые помогают найти ошибки, незаметные на обычных данных;
- при необходимости точки останова (breakpoints) во вкладке Sources, чтобы пройти код по шагам.

## 7. Как работает алгоритм Евклида для нахождения НОД и почему он эффективен?

**Ответ:** Алгоритм основан на свойстве `НОД(a, b) = НОД(b, a % b)`. Мы заменяем пару `(a, b)` на `(b, a % b)`, пока остаток не станет равен `0`. Тогда ответом будет оставшееся число.

Пример для `gcd(54, 24)`:
- `54 % 24 = 6`, получаем пару `(24, 6)`;
- `24 % 6 = 0`, значит `НОД = 6`.

Эффективен он потому, что остаток уменьшается очень быстро (примерно вдвое за два шага), поэтому сложность `O(log(min(a, b)))`. Если искать НОД перебором всех делителей, то понадобилось бы порядка `min(a, b)` шагов.

## 8. Какие edge cases (крайние случаи) нужно учитывать при реализации алгоритмов работы с массивами?

**Ответ:**

- пустой массив `[]` (например, `findMax([])` вернёт `undefined`);
- массив из одного элемента;
- все элементы одинаковые;
- отрицательные числа и ноль;
- уже отсортированный массив и массив в обратном порядке;
- повторяющиеся элементы (`[3, -1, 2, 2]`);
- для бинарного поиска: искомый элемент первый, последний или отсутствует, а ещё важно, что массив должен быть отсортирован;
- очень большие массивы;
- массивы с элементами разных типов (`1` и `"1"` это разные значения).

Большинство этих случаев я проверила в тестах в `tests.js`.

## 9. Как можно улучшить функцию удаления дубликатов для работы с большими массивами?

**Ответ:** Самый простой способ с вложенными циклами или `indexOf` работает за `O(n²)`. Лучше использовать `Set`, он хранит только уникальные значения и проверяет наличие за `O(1)`:

```js
function removeDuplicates(arr) {
    return [...new Set(arr)];
}
```

Общая сложность `O(n)`, при этом порядок первых вхождений сохраняется. Дополнительно можно улучшить:
- для массива объектов использовать `Map` и ключ (например, `id`);
- если массив уже отсортирован, можно убрать повторы за один проход без дополнительной памяти;
- для очень больших данных обрабатывать их частями.

## 10. Какие принципы написания чистого кода вы применили при реализации алгоритмов?

**Ответ:**

- понятные имена функций и переменных (`isPrime`, `findLongestWord`, `pickRandom`);
- каждая функция решает одну задачу;
- ранние возвраты (early return) для крайних случаев, чтобы не было лишней вложенности;
- комментарии со временной сложностью у каждой функции;
- наборы символов и регулярные выражения вынесены в константы (`VOWELS_REGEX`, `PASSWORD_CHARS`);
- входные данные не изменяются (`bubbleSort` сортирует копию массива);
- крайние случаи обработаны и проверены тестами;
- единый стиль оформления: `const` и `let` вместо `var`, одинаковые отступы.
