# Практическая работа №10. JavaScript: работа с функциями

## Ответы на вопросы для самоконтроля

## 1. В чем разница между Function Declaration и Function Expression в контексте hoisting (поднятия)?

**Ответ:** Function Declaration (объявление функции) поднимается целиком: функцию можно вызвать до того места, где она написана.

```js
console.log(square(3)); // 9, работает
function square(x) { return x * x; }
```

Function Expression (функциональное выражение, например `const square = function () {}`) поднимается не полностью. Переменная `const` или `let` до строки с объявлением недоступна, и вызов вызовет `ReferenceError` (временная мёртвая зона). Если использовать `var`, то переменная будет `undefined`, и получится `TypeError: square is not a function`.

```js
console.log(square(3)); // ReferenceError
const square = function (x) { return x * x; };
```

Стрелочные функции ведут себя так же, как Function Expression. В моей работе все функции в `functions.js` написаны как Function Declaration, поэтому `tests.js` может вызывать их независимо от порядка в файле.

## 2. Как работают rest parameters (...args) и в чем их отличие от arguments object?

**Ответ:** Rest parameters собирают все оставшиеся аргументы в настоящий массив:

```js
function sum(...numbers) { /* numbers это массив */ }
```

Отличия от `arguments`:

- `numbers` это настоящий массив, у него есть `map`, `reduce`, `filter`. `arguments` это только массивоподобный объект, его сначала нужно превратить в массив (`Array.from(arguments)`);
- rest указан в списке параметров, поэтому по сигнатуре видно, что функция принимает любое количество аргументов;
- rest можно использовать и в стрелочных функциях, а у них своего `arguments` нет;
- rest может собирать только «хвост» аргументов (`function f(a, ...rest)`), а `arguments` содержит все аргументы.

В моей работе rest используется в `sum(...numbers)` и `compose(...functions)`.

## 3. Что такое замыкание (closure) и как оно связано с лексической областью видимости?

**Ответ:** Замыкание это функция вместе с переменными из того места, где она была создана. Функция «помнит» эти переменные, даже когда внешняя функция уже закончила работу.

Это связано с лексической областью видимости: область видимости переменной определяется тем, где код написан, а не тем, откуда его вызвали. Внутренняя функция видит переменные внешней.

```js
function secretMessage(password, message) {
    return function (inputPassword) {
        return inputPassword === password ? message : "Доступ запрещен";
    };
}
```

После вызова `secretMessage` переменные `password` и `message` остаются внутри возвращённой функции, а снаружи их прочитать нельзя (в тестах я проверяю, что `check.password` равен `undefined`). Ещё замыкания использованы в `memoize` (кэш), `debounce` (таймер) и `throttle` (время последнего вызова).

## 4. Когда следует использовать рекурсию, а когда итерацию? Какие преимущества и недостатки у каждого подхода?

**Ответ:**

**Рекурсия** хорошо подходит для задач с вложенной или древовидной структурой и для задач, которые естественно делятся на такие же подзадачи. Пример из работы: `flatten` разворачивает вложенные массивы любой глубины.

- плюсы: код короткий и близок к математическому определению, удобно обходить деревья и вложенные структуры;
- минусы: каждый вызов занимает место в стеке вызовов, при большой глубине будет `RangeError: Maximum call stack size exceeded`; без дополнительных приёмов бывает медленнее (наивный Фибоначчи считает одно и то же много раз, `O(2ⁿ)`). Гарантированной оптимизации хвостовой рекурсии в JavaScript нет.

**Итерация** (циклы) подходит для простых проходов по данным. Пример: `myMap`, `myFilter`, `myReduce`.

- плюсы: быстрее, не расходует стек, нет ограничения по глубине;
- минусы: для деревьев и вложенных структур код получается сложнее (нужен свой стек).

Выбор такой: если структура линейная, то цикл, если вложенная, то рекурсия. Тяжёлую рекурсию можно ускорить мемоизацией, как в `fibonacciMemo`.

## 5. Как работают функции высшего порядка и какие встроенные методы массивов являются таковыми?

**Ответ:** Функция высшего порядка это функция, которая принимает другую функцию как аргумент или возвращает функцию. Это возможно, потому что в JavaScript функции являются значениями (их можно передавать и возвращать, как числа или строки).

Встроенные методы массивов, которые принимают функцию: `map`, `filter`, `reduce`, `forEach`, `find`, `findIndex`, `some`, `every`, `sort` (с функцией сравнения), `flatMap`. Ещё к этому относятся `setTimeout` и обработчики событий.

В моей работе:

- `myMap`, `myFilter`, `myReduce` принимают функцию (callback) и вызывают её для каждого элемента с аргументами `(элемент, индекс, массив)`;
- `compose`, `curry`, `memoize`, `debounce`, `throttle` и `createValidator` принимают или возвращают функции.

```js
myMap([1, 2, 3], (x) => x * 2); // [2, 4, 6]
```

## 6. Что такое каррирование и какие практические преимущества оно дает?

**Ответ:** Каррирование превращает функцию от нескольких аргументов в цепочку функций от одного аргумента: `f(a, b, c)` превращается в `f(a)(b)(c)`.

```js
const add3 = curry((a, b, c) => a + b + c);
add3(1)(2)(3);   // 6
add3(1, 2)(3);   // 6
```

Преимущества:

- **частичное применение**: можно один раз «зафиксировать» часть аргументов и использовать получившуюся функцию много раз (`const add10 = add3(10)`);
- удобно передавать в `map`, `filter` и другие функции высшего порядка (`myMap([1, 2, 3], curry((a, b) => a + b)(10))` даст `[11, 12, 13]`);
- функции получаются более гибкими и лучше сочетаются друг с другом (`compose`, `pipe`).

Недостатки: небольшие накладные расходы, а ещё мой `curry` определяет число аргументов по `fn.length`, поэтому с функциями с параметрами по умолчанию и rest он работает не так.

## 7. Как работает мемоизация и в каких случаях ее использование наиболее эффективно?

**Ответ:** Мемоизация запоминает результат вызова функции для набора аргументов. При повторном вызове с теми же аргументами результат берётся из кэша, а не считается заново. В моей `memoize` кэш это `Map`, а ключ строится из аргументов через `JSON.stringify`.

Наиболее эффективна, когда:

- функция **чистая** (результат зависит только от аргументов, побочных эффектов нет);
- вычисление **дорогое**, а одни и те же аргументы встречаются часто;
- есть много повторных подзадач, как в рекурсивном Фибоначчи: `fibonacciMemo(50)` считается мгновенно (`12586269025`), а без кэша заняло бы очень много времени.

Не подходит для функций с побочными эффектами или случайностью (`Math.random`, `Date.now`), для очень дешёвых вычислений, а также когда аргументов слишком много разных и кэш будет бесконечно расти (тогда нужен лимит, например LRU-кэш).

## 8. В чем разница между debounce и throttle и когда следует использовать каждый подход?

**Ответ:** Обе техники ограничивают частоту вызова функции, но по-разному.

- **debounce** откладывает вызов до тех пор, пока вызовы не прекратятся на заданное время. Каждый новый вызов сбрасывает таймер. В итоге функция сработает **один раз после паузы**. Пример: при быстром вводе в строку поиска запрос отправляется, когда человек перестал печатать. Также подходит для автосохранения и для события `resize` (когда закончили менять размер окна).
- **throttle** пропускает вызовы не чаще, чем раз в заданный интервал. Функция срабатывает **регулярно во время потока событий**. Пример: обработчик прокрутки страницы или движения мыши, защита кнопки от частых нажатий.

Пример из моих тестов: пять быстрых вызовов подряд. `debounce` выполнит функцию один раз (в конце, с аргументами последнего вызова), а `throttle` выполнит первый вызов сразу и ещё один в конце интервала.

## 9. Как функции-генераторы (function*) отличаются от обычных функций?

**Ответ:** Обычная функция выполняется до конца и возвращает одно значение. Генератор (`function*`) при вызове ничего не выполняет, а возвращает объект-итератор. Код внутри запускается по частям при вызове `next()`. Оператор `yield` приостанавливает функцию и отдаёт очередное значение, а при следующем `next()` она продолжает с того же места, сохранив все переменные.

```js
function* fibonacciGenerator() {
    let [current, next] = [0, 1];
    while (true) {
        yield current;
        [current, next] = [next, current + next];
    }
}
take(fibonacciGenerator(), 8); // [0, 1, 1, 2, 3, 5, 8, 13]
```

Главные отличия: генератор может быть **бесконечным** (значения считаются лениво, только когда нужны), хранит состояние между вызовами, работает с `for...of` и spread, умеет принимать значения через `next(value)`. Применяют для ленивых последовательностей, обхода больших структур, постраничной загрузки и в асинхронном коде (на этом основан `async/await`).

## 10. Какие принципы функционального программирования вы применили в ходе работы и в чем их benefits?

**Ответ:**

- **Чистые функции**: `sum`, `myMap`, `myFilter`, `createUser`, `createValidator` зависят только от аргументов и не меняют внешнее состояние. Их легко тестировать и понимать.
- **Неизменяемость**: функции не меняют входные данные (`myMap` и `myFilter` возвращают новый массив, `createValidator` копирует опции), что я проверяла в тестах.
- **Функции высшего порядка и замыкания**: `compose`, `curry`, `memoize`, `secretMessage`.
- **Композиция**: из маленьких функций собирается конвейер (`compose(sumAll, squareAll, onlyEven)` для суммы квадратов чётных чисел).
- **Декларативный стиль**: `filter`, `map`, `reduce` описывают что нужно получить, а не как перебирать элементы циклом.
- **Рекурсия** вместо циклов там, где структура вложенная (`flatten`).

Преимущества: код предсказуемый (одинаковые аргументы дают одинаковый результат), его проще тестировать (150 тестов проверяют функции независимо друг от друга), меньше скрытых ошибок из-за общего состояния, функции можно переиспользовать и комбинировать. Побочные эффекты (таймеры в `debounce` и `throttle`) я сознательно спрятала внутри функций и ограничила.
