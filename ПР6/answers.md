# Практическая работа №6. Адаптивная верстка

## Ответы на вопросы для самоконтроля

## 1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?

**Ответ:** Это тег в `<head>`, который говорит мобильному браузеру, как масштабировать страницу:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

`width=device-width` задаёт ширину области просмотра равной реальной ширине экрана устройства, а `initial-scale=1.0` задаёт начальный масштаб без увеличения и уменьшения.

Без этого тега мобильный браузер считает, что страница рассчитана на компьютер (виртуальная ширина около 980px), рисует её в такой ширине и уменьшает под экран. Текст получается мелким, а медиа-запросы по ширине срабатывают не так, как нужно. Поэтому без viewport адаптивная верстка просто не работает. Запрещать пользователю масштабировать (`user-scalable=no`) не стоит, это плохо для доступности.

## 2. Какие основные подходы к созданию адаптивных макетов вы использовали в работе (Fluid, Adaptive, Responsive)?

**Ответ:**

- **Fluid (резиновая верстка)** это относительные размеры, которые растягиваются вместе с окном: проценты, `fr`, `vw`, `clamp()`.
- **Adaptive (адаптивная в узком смысле)** это несколько фиксированных макетов под разные ширины, которые переключаются на определённых брейкпоинтах.
- **Responsive** это сочетание fluid, медиа-запросов и гибких изображений.

В работе использован responsive-подход. От fluid здесь `.container` с `width: 100%` и `max-width`, сетка на `fr`, размеры текста через `clamp()` и картинка с `max-width: 100%`. От adaptive здесь медиа-запросы на 1024px, 768px и 480px, на которых меняется структура: карточки 3 → 2 → 1 в ряд, обычное меню превращается в кнопку-бургер.

## 3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?

**Ответ:** При Mobile First сначала пишутся стили для маленького экрана, а потом для больших экранов добавляются улучшения через `min-width`:

```css
.features-grid { grid-template-columns: 1fr; }

@media (min-width: 768px) {
    .features-grid { grid-template-columns: repeat(3, 1fr); }
}
```

Преимущества:

- телефону достаются самые простые стили, ему не надо загружать и потом отменять сложные десктопные;
- меньше переопределений, поэтому код чище;
- заставляет сначала продумать главное содержимое;
- сейчас большая часть трафика мобильная, и поисковики оценивают в первую очередь мобильную версию.

При Desktop First всё наоборот: пишется версия для компьютера, потом через `max-width` она упрощается для маленьких экранов, и приходится отменять много правил. В моей работе использован именно Desktop First, как в задании (все запросы через `max-width`). Чтобы переделать на Mobile First, нужно поменять базовые стили местами с мобильными и заменить `max-width` на `min-width`.

## 4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему (%, rem, em, vw/vh)?

**Ответ:**

| Единица | Относительно чего | Где использовать |
|---|---|---|
| `rem` | размер шрифта корневого элемента `html` | шрифты, отступы, размеры блоков; хорошо масштабируется |
| `em` | размер шрифта родителя | размеры внутри компонента, например отступы кнопки |
| `%` | размер родителя | ширина блоков, картинок |
| `vw` / `vh` | 1% ширины / высоты окна | крупные заголовки, секции на весь экран, внутри `clamp()` |

Для адаптивной верстки лучше всего подходят относительные единицы, а `px` для размеров текста лучше не использовать. Обычно шрифты и отступы задают в `rem` (учитываются настройки браузера пользователя), ширину блоков в `%` или `fr`, а `vw` применяют вместе с `clamp()`. В моей работе использованы `rem`, `%`, `fr` и `vw`, а размер шрифта у `html` задан в процентах.

## 5. Как функция clamp() помогает создавать адаптивную типографику?

**Ответ:** `clamp(min, предпочтительное, max)` возвращает среднее значение, но не меньше минимума и не больше максимума. С `vw` в середине размер текста плавно меняется вместе с шириной окна, но никогда не становится слишком мелким или огромным. Так не нужны отдельные медиа-запросы для каждого размера шрифта.

Пример из работы:

```css
.hero h2 {
    font-size: clamp(1.6rem, 5vw, 2.8rem);
}
```

При базовом шрифте 16px минимум составляет 25,6px, максимум 44,8px. Между ширинами примерно 512px и 896px заголовок плавно растёт, на телефоне он остаётся 25,6px, а на большом мониторе не больше 44,8px. Минимум и максимум удобно писать в `rem`, чтобы сохранялась настройка размера шрифта в браузере.

## 6. Какие основные брейкпоинты вы использовали и как определили эти значения?

**Ответ:** Я использовала три брейкпоинта:

- **1024px** (планшеты): карточки в две колонки, контент и боковая панель встают друг под другом, контейнер сужается;
- **768px** (мобильные): появляется меню-бургер, шрифт немного уменьшается;
- **480px** (маленькие телефоны): одна колонка, меньшие отступы и размеры текста.

Эти значения даны в задании, они примерно соответствуют типичным устройствам (планшет в альбомной ориентации, планшет в портретной, телефоны). Вообще правильнее выбирать брейкпоинт там, где макет начинает ломаться, а не под конкретное устройство. Для этого нужно медленно менять ширину окна в DevTools. Так, при проверке на ширине около 900px я заметил, что в шапке не помещается меню, и добавил для планшетов более компактные отступы и `white-space: nowrap`.

## 7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.

**Ответ:** Медиа-запрос применяет блок CSS только тогда, когда выполняется условие: ширина окна, ориентация экрана, тема системы и так далее. Благодаря этому одну и ту же страницу можно оформлять по-разному на разных устройствах: менять число колонок, показывать и скрывать элементы, менять размеры.

```css
@media (max-width: 768px) {
    .nav-toggle { display: block; }
    .nav-menu   { display: none; }
}
```

Условия можно объединять: `@media (min-width: 768px) and (max-width: 1024px)`. Есть и другие условия, например `orientation: landscape` и `prefers-color-scheme: dark`.

## 8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?

**Ответ:**

- `max-width: 768px` означает «ширина окна **не больше** 768px». Такие запросы используют при подходе Desktop First, когда стили идут от большого экрана к малому.
- `min-width: 768px` означает «ширина окна **не меньше** 768px». Их используют при Mobile First, когда стили идут от малого экрана к большому.

Важно и расположение: запросы `max-width` пишут от большего значения к меньшему (1024 → 768 → 480), а `min-width` от меньшего к большему, чтобы более узкие или широкие условия переопределяли предыдущие. В моей работе все запросы `max-width`, они идут в порядке 1024px, 768px, 480px и находятся в конце файла стилей.

## 9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?

**Ответ:** Основное правило:

```css
img {
    max-width: 100%;
    height: auto;
}
```

`max-width: 100%` не даёт картинке быть шире родителя, а `height: auto` сохраняет пропорции. В работе это сделано в `reset.css`, а у картинки в статье ещё есть класс `.responsive-img` с `width: 100%` и `height: auto`.

Дополнительно можно:

- указывать атрибуты `width` и `height` в HTML, чтобы страница не прыгала при загрузке;
- использовать `srcset` и `sizes` или тег `<picture>`, чтобы телефон загружал маленькую картинку, а компьютер большую;
- использовать `object-fit: cover`, если нужно обрезать картинку по заданной высоте;
- добавлять `loading="lazy"` для отложенной загрузки.

В моей работе картинка это SVG-иллюстрация, она векторная и без потери качества масштабируется на любой экран.

## 10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?

**Ответ:** Главный инструмент это DevTools (F12). В нём есть:

- **режим адаптивного дизайна** (Ctrl+Shift+M): можно тянуть ширину окна, выбирать устройства (iPhone, iPad и другие), поворачивать экран, менять плотность пикселей и эмулировать медленную сеть;
- **панель медиа-запросов** над экраном, по клику на её полоску ширина окна выставляется на нужный брейкпоинт;
- вкладка **Elements** и панель **Styles**, где видно, какие правила и какие `@media` сейчас применяются, и где значения можно менять прямо в браузере;
- вкладка **Computed**, где показаны итоговые размеры;
- вкладка **Rendering**, в которой можно эмулировать, например, тёмную тему (`prefers-color-scheme`);
- **Lighthouse** для проверки удобства страницы на мобильных.
