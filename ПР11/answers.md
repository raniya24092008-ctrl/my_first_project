# Практическая работа №11. JavaScript: манипуляции DOM-деревом

## Ответы на вопросы для самоконтроля

## 1. В чем разница между innerHTML и textContent и когда следует использовать каждый метод?

**Ответ:**

- `textContent` читает и записывает **обычный текст**. Если записать в него строку с тегами, они покажутся на странице как символы и не станут элементами.
- `innerHTML` читает и записывает **HTML-разметку**: браузер разбирает строку и создаёт из неё настоящие элементы.

```js
el.textContent = '<b>привет</b>'; // на странице будет написано: <b>привет</b>
el.innerHTML = '<b>привет</b>';   // на странице появится жирное слово: привет
```

Что использовать:

- для вывода текста, особенно **введённого пользователем**, нужно использовать `textContent`: он быстрее и безопасен. Если вставить пользовательскую строку через `innerHTML`, можно получить XSS-атаку (например, `<img src=x onerror=...>` выполнит чужой код);
- `innerHTML` оправдан только для заранее известной разметки, которой доверяешь.

В моей работе везде используется `textContent`: в `createCard`, `addListItem`, `displayFormErrors`. В тестах я проверила, что строка `<img src="x" onerror="...">` в карточке остаётся текстом и код не выполняется. Ещё `innerHTML` при записи заменяет все вложенные элементы, а их обработчики пропадают.

## 2. Как работает делегирование событий (event delegation) и какие преимущества оно дает при работе с динамическими элементами?

**Ответ:** Делегирование это когда вместо обработчика на каждом элементе ставится **один обработчик на родителе**. Это возможно благодаря всплытию событий: клик по кнопке «поднимается» вверх до родителя. В обработчике по `event.target` определяется, где именно кликнули.

```js
list.addEventListener('click', function (event) {
    const deleteButton = event.target.closest('.delete-btn');
    if (deleteButton) {
        deleteButton.closest('.list-item').remove();
    }
});
```

Преимущества:

- работает для **элементов, которые добавят позже** (новые пункты списка сразу удаляются, обработчик на них навешивать не нужно);
- меньше обработчиков, значит меньше памяти и проще код;
- нет необходимости снимать обработчики при удалении элемента.

В `setupListEvents` один обработчик на `#dynamic-list` обрабатывает удаление всех пунктов. Недостатки: событие должно всплывать (`focus` и `blur` не всплывают, для них есть `focusin` и `focusout`), а `stopPropagation()` в дочернем элементе сломает делегирование.

## 3. Какие методы используются для поиска элементов в DOM и в чем разница между getElementById, querySelector и querySelectorAll?

**Ответ:**

| Метод | Что ищет | Что возвращает |
|---|---|---|
| `getElementById('id')` | элемент по id | один элемент или `null` |
| `querySelector('css')` | первый элемент по CSS-селектору | один элемент или `null` |
| `querySelectorAll('css')` | все элементы по CSS-селектору | статичный `NodeList` (может быть пустым) |
| `getElementsByClassName`, `getElementsByTagName` | по классу или тегу | «живая» `HTMLCollection` |

Разница:

- `getElementById` самый быстрый, но ищет только по id (в селекторе `#` не нужен);
- `querySelector` гибкий (`.special`, `#parent-element .child`, `input[type="text"]`), но возвращает только первое совпадение;
- `querySelectorAll` возвращает все совпадения, но это **снимок**: если потом добавить подходящий элемент, коллекция не изменится. Живая `HTMLCollection` обновляется сама.

В работе: `getElementById` в `getRequiredElement`, `querySelector('.special')` в `findSpecialChild`, `querySelectorAll` в тестах для списка.

## 4. Как предотвратить стандартное поведение элемента при обработке событий и когда это необходимо?

**Ответ:** Для этого вызывают `event.preventDefault()`. Он отменяет действие браузера по умолчанию, но само событие продолжает всплывать.

Когда это нужно:

- **отправка формы** (`submit`): без отмены страница перезагрузится и уйдут данные. Если валидация и вывод результата делаются на JavaScript, отправку нужно отменить;
- клик по ссылке `<a>` (чтобы не переходить по адресу);
- контекстное меню, перетаскивание, прокрутка колесом на своих компонентах.

```js
function handleFormSubmit(event) {
    event.preventDefault(); // страница не перезагружается
    // проверка данных и вывод результата
}
```

Важно: событие должно быть отменяемым (`event.cancelable`), а обработчики с флагом `passive: true` отменить действие не могут. Проверить результат можно через `event.defaultPrevented`, я использую это в тестах формы. Не путать с `stopPropagation()`: он останавливает всплытие, а не действие браузера.

## 5. В чем разница между classList.add() и className для работы с CSS классами?

**Ответ:**

- `className` это **строка** со всеми классами сразу. Если записать в неё значение, все прежние классы заменятся.
- `classList` это специальный объект с методами для работы с отдельными классами: `add`, `remove`, `toggle`, `contains`, `replace`.

```js
el.className = 'active';           // старые классы потеряны
el.className += ' active';         // нужно следить за пробелом, возможны дубли
el.classList.add('active');        // добавляет один класс и не трогает остальные
el.classList.toggle('active');     // включает или выключает
el.classList.contains('active');   // проверка
```

`classList` удобнее и безопаснее: нет ручной работы со строкой, не получается дубликатов, можно добавить несколько классов сразу (`add('a', 'b')`). `className` годится, когда нужно полностью задать список классов. В работе я использую `classList.toggle('active-style')`, и в тесте проверяю, что другие классы элемента остаются на месте.

## 6. Как создать новый элемент и добавить его в DOM несколькими способами? Какой способ наиболее эффективен?

**Ответ:** Способы:

1. `document.createElement('div')` и затем добавить: `appendChild`, `append`, `prepend`, `before`, `after`, `insertBefore`, `replaceWith`;
2. `innerHTML` и `insertAdjacentHTML('beforeend', '<li>...</li>')`: вставка строки с разметкой;
3. `cloneNode(true)`: копия существующего элемента;
4. тег `<template>`: заготовка, которую копируют и вставляют.

Что эффективнее: каждое изменение живого DOM может заставить браузер заново рассчитывать раскладку (reflow) и перерисовывать (repaint), поэтому элементы лучше **собирать вне документа и вставлять один раз** (в `DocumentFragment` или в оторванный родитель). Так сделан `createList`: сначала собирается `ol` с пунктами, и только потом он добавляется в `#target1`. Для безопасности и ясности `createElement` вместе с `textContent` предпочтительнее строки с HTML. Для очень большого количества однотипных элементов быстро работает и `insertAdjacentHTML`, но только с доверенными данными.

## 7. Что такое всплытие событий (event bubbling) и как работает метод stopPropagation()?

**Ответ:** Событие проходит три фазы: сначала **погружение** (capturing) от `document` вниз к цели, потом срабатывает на самой цели (**target**), потом **всплытие** (bubbling): событие поднимается от цели через всех родителей вверх до `document`. По умолчанию обработчики срабатывают на этапе всплытия.

Например, клик по кнопке «Удалить» вызовет обработчики сначала на кнопке, потом на `li`, потом на `ul` и так далее. На этом основано делегирование. Нажатие клавиши в поле ввода тоже всплывает до `document`, поэтому мой обработчик клавиш на документе видит и такие нажатия (я проверила это в тесте).

`event.stopPropagation()` останавливает дальнейшее всплытие: обработчики на родителях не вызовутся (остальные обработчики на том же элементе выполнятся, чтобы остановить и их, есть `stopImmediatePropagation()`). Использовать его нужно редко: он ломает делегирование и сторонние скрипты (например, аналитику). Чаще достаточно проверить `event.target`.

## 8. Как получить данные из формы и в чем разница между методами сбора form data?

**Ответ:** Основные способы:

```js
// 1. Читать значения полей вручную
const name = document.getElementById('user-name').value;

// 2. Через коллекцию form.elements
const email = form.elements['user-email'].value;

// 3. Через FormData (по атрибутам name)
const data = new FormData(form);
const obj = Object.fromEntries(data);   // обычный объект
const interests = data.getAll('interests'); // если значений несколько
```

Различия:

- `FormData` собирает **все поля с атрибутом `name`** сразу и подходит для отправки на сервер (`fetch(url, { method: 'POST', body: data })`), в том числе с файлами. Не попадут отключённые (`disabled`) поля и неотмеченные чекбоксы;
- чтение через `.value` позволяет сразу привести тип (например, `Number(age)`) и обрезать пробелы, но кода больше.

В моей работе у полей формы есть только `id` без `name`, поэтому `FormData` вернул бы пустой результат. Поэтому я собираю данные по id через `.value` и сама привожу возраст к числу.

## 9. Какие события используются для обработки ввода данных и в чем разница между input, change и keyup?

**Ответ:**

- **input** срабатывает **при каждом изменении значения**: набор текста, вставка мышью, удаление, автозаполнение, голосовой ввод. Подходит для реакции в реальном времени. Именно его я использую в `setupInputDisplay`.
- **change** срабатывает, когда значение **зафиксировано**: для текстового поля при потере фокуса или нажатии Enter (если текст изменился), а для `checkbox`, `radio` и `select` сразу при выборе. Подходит для итоговой проверки и для переключателей.
- **keyup** срабатывает при **отпускании клавиши** (есть ещё `keydown` при нажатии). Связан с клавиатурой, а не со значением: сработает на стрелки и Shift, где текст не менялся, и не сработает, если текст вставили мышью. Подходит для горячих клавиш.

Поэтому для отображения текста нужен `input`: `keyup` пропустил бы вставку мышью. Для добавления элемента по Enter в `setupListEvents` я использую `keydown`.

## 10. Как оптимизировать производительность при частых манипуляциях с DOM?

**Ответ:**

- **Уменьшать число изменений живого DOM**: собирать элементы вне документа (`DocumentFragment`, оторванный родитель) и вставлять один раз (так в `createList`);
- **кэшировать найденные элементы** в переменных, а не искать их заново в каждой итерации цикла;
- **не чередовать чтение и запись** размеров и стилей (`offsetHeight` и изменение `style`), потому что это вызывает лишние перерасчёты раскладки (layout thrashing): сначала всё прочитать, потом всё записать;
- менять **классы** (`classList`) вместо множества inline-стилей;
- для анимации использовать `transform` и `opacity` (их браузер рисует на GPU), а не `width`, `top` или `left`, и запускать анимацию через CSS transitions или `requestAnimationFrame` (так сделан `animateElement`);
- использовать **делегирование событий** вместо множества обработчиков;
- ограничивать частые события (`scroll`, `resize`, `input`) через `debounce` и `throttle`;
- использовать `textContent` вместо `innerHTML` для текста, а для очень длинных списков показывать только видимую часть (виртуализация).
